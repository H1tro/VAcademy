# Переход VAcademy на Supabase

Сначала выполните настройку, затем публикуйте новую версию. Регистрация, вход, профили, решения, рейтинг, Codeforces, заявки преподавателей, задания и поддержка теперь используют Supabase. Учебные PDF и загрузки Vercel Blob остаются в прежнем хранилище.

## 1. База данных

Откройте свой проект Supabase → SQL Editor → New query. Скопируйте **весь** файл `supabase/migrations/202610100001_vacademy.sql` и нажмите Run. Он создаёт таблицу `app_documents`, функции атомарной записи, проверку регистрации и очистку данных при удалении аккаунта. Повторное выполнение сохраняет существующие записи.

Включён RLS; прямой доступ anon/authenticated к данным приложения закрыт. Таблицу читает и изменяет только сервер через secret/service_role key, после проверки пользователя и роли в API. Не создавайте политику «разрешить всем» для `app_documents`. Отдельная демонстрационная страница `/supabase` использует `todos`; эта таблица для основной платформы не нужна.

## 2. Переменные окружения

В `.env.local` уже есть адрес проекта и publishable key. Добавьте серверный ключ из Supabase → Settings → API Keys:

```env
SUPABASE_SECRET_KEY=ваш_серверный_ключ
NEXT_PUBLIC_APP_URL=http://localhost:9002
```

Вместо `SUPABASE_SECRET_KEY` поддерживается старый `SUPABASE_SERVICE_ROLE_KEY`. Серверный ключ **не** должен называться `NEXT_PUBLIC_*`, попадать в Git или сообщения чата. `.env.local` исключён из Git.

На хостинге добавьте `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, серверный ключ и `NEXT_PUBLIC_APP_URL=https://ваш-домен`. После изменения переменных требуется новая сборка. Остальные ключи AI, Telegram, Vercel Blob и Resend сохраняются отдельно.

## 3. Авторизация и письма

В Authentication → Sign In / Providers включите Email. Для опубликованного сайта оставьте подтверждение email включённым. В Authentication → URL Configuration задайте **Site URL** равным адресу реально опубликованной версии с Supabase (не оставляйте `localhost:3000`). Настройка `NEXT_PUBLIC_APP_URL` в Vercel не меняет Site URL в Supabase. Добавьте разрешённые Redirect URLs:

- `http://localhost:9002/auth/callback` для разработки;
- `https://ваш-домен/auth/callback` для публикации;
- `https://ваш-домен/auth/callback?next=/reset-password` для сброса пароля;
- `http://localhost:9002/auth/callback?next=/reset-password` для локальной проверки сброса.

Регистрация создаёт профиль через транзакционный триггер, включая возрастную группу, версию документов и время принятия. Возраст младше 13 лет отклоняется также на уровне базы. Поле роли из пользовательских metadata игнорируется: новый аккаунт всегда ученический. Преподаватель подаёт заявку, администратор подтверждает её.

Если подтверждение включено, после регистрации появится просьба проверить почту. Стандартная PKCE-ссылка работает в браузере, в котором начата регистрация. Для подтверждения в другом браузере можно настроить шаблон Confirm signup:

```html
<a href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=email">Подтвердить email / Confirm email</a>
```

Вход содержит ссылки «Забыли пароль?» и «Письмо подтверждения не пришло?». После регистрации без активной сессии появляется повторная отправка. Формы используют Supabase Auth, показывают паузу 60 секунд и ошибки лимита доставки. Успешный запрос не гарантирует доставки и не раскрывает наличие аккаунта. Истёкшая ссылка ведёт на форму нового запроса. Для сброса открывается `/reset-password`; новый пароль записывается через Supabase только в действующей сессии, затем выполняется локальный выход.

Стандартный шаблон Reset password должен использовать `{{ .ConfirmationURL }}`, чтобы Supabase сохранил адрес возврата из запроса. Если используете подтверждение через хеш в другом браузере, шаблон Reset password может содержать:

```html
<a href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=recovery">Сбросить пароль / Reset password</a>
```

Для доставки писем реальным пользователям настройте собственный SMTP в Supabase. Подтверждения удаления аккаунта отправляются через Resend: нужны `RESEND_API_KEY` и разрешённый адрес отправителя в `RESEND_FROM_EMAIL`. Без них эта функция не настроена.

Если письмо удаления не отправляется:

Пользователь с паролем может удалить аккаунт без письма в `/profile/edit`: ввести текущий пароль и отметить подтверждение необратимого удаления. Сервер проверяет действующую авторизацию, получает email из Supabase, проверяет пароль отдельным клиентом и совпадение ID перед удалением. Временная сессия проверки пароля закрывается. Чужой ID или email из тела запроса не используется. Ошибки пароля и лимиты Supabase не позволяют выполнить удаление.

- В Resend добавьте собственный домен и подтвердите DNS-записи. Адрес `onboarding@resend.dev` предназначен только для отправки тестовых писем владельцу Resend; Gmail и общий домен `vercel.app` нельзя использовать как собственный домен отправителя.
- В Vercel добавьте `RESEND_API_KEY` как Secret и `RESEND_FROM_EMAIL` как Config (например, `VAcademy <accounts@ваш-домен>`), для окружений, где используется сайт. Затем выполните Redeploy.
- Проверьте разрешения ключа на отправку с выбранного домена. В логах функции `request-deletion` смотрите событие `Deletion email rejected`: 401/403/422 требуют проверки ключа, домена и отправителя; 429 означает ограничение отправки. Код не пишет адрес получателя, ссылку подтверждения или секреты в логи.
- Настройка SMTP в Supabase сама по себе не настраивает этот отдельный запрос к Resend. При сбое отправки аккаунт сохраняется, а созданный токен удаления очищается.

## 4. Администратор

Зарегистрируйте и подтвердите свой аккаунт. В Authentication → Users скопируйте его Supabase UUID и добавьте на сервере `ADMIN_UIDS=UUID`. Для нескольких администраторов используйте запятую. Старые Firebase UID сюда не подходят. Не помещайте сюда UUID заявителей на преподавательскую роль.

## 5. Проверка и публикация

```bash
npm install
npm run check:i18n
npm run check:legal
npm run check:supabase
npm run check:auth
npm run check:database
npm run check:access
npm run check:submissions
npm run typecheck
npm run build
```

Эти проверки используют локальный PostgreSQL и тестовые данные; они не читают ваш Supabase. После настройки вручную проверьте регистрацию, письмо подтверждения, вход/выход, сохранение профиля, решение задачи, заявку преподавателя, одобрение администратором и обратную связь. Облачная схема не устанавливается командой сборки.

## Прежние аккаунты и данные

Этот SQL не переносит пользователей, пароли, профили или результаты из Firebase. Старый Firebase UID отличается от нового Supabase UUID. Для сохранения старых аккаунтов необходим отдельный контролируемый экспорт, импорт пользователей и сопоставление идентификаторов во всех связанных записях; простое копирование документов по старым UID недостаточно. До этого старый пароль и прежний прогресс не появятся в новом аккаунте. Старую базу пока сохраните; удалять её для переключения кода не требуется. Экспорт реальных данных в этой задаче не выполнялся.
